How the data is sourced and checked

Independent and unofficial · Six named offices · Last reviewed 17 November 2026

Every record on this site comes from a published Irish visa office file or processing-date page. This page lists those sources, the checks applied to each row, and the limits of the data.

How a record is checked

  1. Fetch the published source. The scheduled job downloads the office page or file and keeps its source URL.
  2. Preserve the report date. Each file keeps the date the office published it, separately from the decision date on a row.
  3. Normalize without inventing rows. Decision rows are stored as [date, applicationNumber, decision]. A missing office file stays a gap.
  4. Deduplicate per office. A repeated application number is counted once, at its most recent report date. Corrections are counted rather than hidden.
  5. Publish the evidence. The JSON files, manifest and fetch times are public, so a figure can be checked against the office that published it.

What the data cannot tell you

  • It is not an official decision. The office handling your application remains the only authority.
  • A report date is not every decision date. Weekly reports use a report-period end date, not the date of each individual decision.
  • It does not predict an outcome. Any processing-date estimate is a transparent baseline, not a promise or a queue position.
  • It cannot speed up an application. No third-party tracker can change a visa decision or processing time.
  • Coverage can have gaps. Offices publish on different schedules, and older archive files may be unavailable.

Public data and corrections

Inspect the decision data, the data manifest and the live data status. The code is in the public repository.
