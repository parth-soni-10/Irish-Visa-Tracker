About the Irish Visa Decision Tracker

Independent project by Parth Soni • Dublin, Ireland • Last updated 21 November 2026

Six Irish visa offices – New Delhi, Beijing, Abu Dhabi, Abuja, Ankara and Dublin – publish visa decision files and totals: flat lists with no history, no search and no trends. This site keeps a running, searchable record of those decisions and tracks the processing queues that matter alongside them.

What it tracks

  • Embassy visa decisions – each published application number, its decision date and whether it was approved or refused, searchable by application number.
  • Daily summaries – approved and refused counts for each published day, with the applications behind those counts available on demand.
  • Stamp 1G processing – the application date ISD is currently processing, how many days behind that is, and how the lag has moved over time.
  • Employment permits – the processing date reached for each permit category, with trends and projections.
  • Community timelines – waits shared by visitors, merged into the public data file each night. They are anecdotes, not a statistical sample.

Where the data comes from

Visa decision rows come from the published reports of six Irish visa offices: New Delhi, Beijing, Abu Dhabi, Abuja, Ankara and Dublin. Stamp 1G and employment permit figures come from the published processing dates on ISD and DETE. New data is added automatically, and each page shows the date of its latest observation.

The underlying data is public: visa decisions, Stamp 1G observations, employment permits and community timelines.

How the data is sourced and checked

Every record comes from a published Irish visa office file or processing-date page. This section lists those sources, the checks applied to each row, and the limits of the data.

How a record is checked

  1. Fetch the published source. The scheduled job downloads the office page or file and keeps its source URL.
  2. Preserve the report date. Each file keeps the date the office published it, separately from the decision date on a row.
  3. Normalize without inventing rows. Decision rows are stored as [date, applicationNumber, decision]. A missing office file stays a gap.
  4. Deduplicate per office. A repeated application number is counted once, at its most recent report date. Corrections are counted rather than hidden.
  5. Publish the evidence. The JSON files, manifest and fetch times are public, so a figure can be checked against the office that published it.

What the data cannot tell you

  • It is not an official decision. The office handling your application remains the only authority.
  • A report date is not every decision date. Weekly reports use a report-period end date, not the date of each individual decision.
  • It does not predict an outcome. Any processing-date estimate is a transparent baseline, not a promise or a queue position.
  • It cannot speed up an application. No third-party tracker can change a visa decision or processing time.
  • Coverage can have gaps. Offices publish on different schedules, and older archive files may be unavailable.

Inspect the decision data, the data manifest and the live data status. The code is in the public repository. Corrections are logged in the correction ledger.

Who runs it

This is a personal project by Parth Soni, a data analyst in Dublin. It started as a way to answer a simple question – has my application been decided yet? – without opening a different spreadsheet every morning. The code and data are public so the record can be checked and reused.

There is no advertising, no paid tier and no account.

What it is not

This is an unofficial tracker. It is not affiliated with, endorsed by or operated by the Embassy of Ireland, ISD, DETE or any Irish government body. It is not immigration advice, cannot speed up an application and cannot guarantee an outcome. For a decision on your own case, use the official channels.

Corrections welcome. If a row is wrong or a processing date is out of date, email soni.soni.parth@gmail.com or open an issue with the date and source. Corrections are checked against the published source before a change.
