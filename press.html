All six offices.

The tracker is an independent, searchable record of the decision files published by six Irish visa offices. It is useful for a story about published decision volume, approval shares or the shape of the official files — never as a prediction for an individual application.

What the tracker records

For each office the tracker stores the published application number, decision and the date basis the office uses: a daily cumulative file for New Delhi, weekly report periods for Abu Dhabi, Abuja and Ankara, and dated snapshots for Beijing and Dublin. The latest-file totals are New Delhi: 44,097; Beijing: 14,425; Abu Dhabi: 232; Abuja: 99; Ankara: 217; Dublin: 4,848.

The files do not contain visa category, nationality, refusal reason or applicant demographics. Any statement about those would be unsupported by this data.

Story angles the data supports

  • Approval shares differ sharply by office, and by file kind. The latest weekly reports run from 34.3% to 88.5% approved; the cumulative and snapshot files sit at 61.6% to 84.2% and each describes a whole list rather than one week, so the two sets are not compared as a single range. The data study sets out the figures and caveats.
  • Publication volume is not demand. Weekly reports show how many decisions an office published in a period, not how many people applied.
  • New Delhi's cumulative file is measurable day by day. Archived file dates show how the list grew across the run of file dates in November 2026.
  • Gaps are visible. The tracker records missing reports as gaps rather than estimating them.

Monthly story package

Each monthly report carries a one-finding package: a headline number, a publication-ready sentence, the method note, a pitch you can send and the CSV files behind it. The latest package sits on the monthly report; each office page carries its own analysis of the published series.

DOI-backed snapshots and data catalogs

A DOI is minted by depositing a dated snapshot with a repository such as Zenodo; it cannot be created by the site itself. The tracker publishes the snapshot files, CITATION.cff and Zenodo deposit metadata, so a deposit can point at an immutable version and the study can cite the DOI once it exists.

The office pages already carry Dataset markup with a licence, a landing page and download URLs, which is what Google Dataset Search reads; the data study is the human-readable version of the same definition. The markup gains a DOI identifier when a deposit returns one; the Dataset record is then registrable with DataCite, OpenAIRE and re3data. None of those registrations exist yet, and this page does not claim otherwise.

Publishing the DOI requires the maintainer's Zenodo account. Until then, cite the study URL and the data date above. Corrections are logged in the correction ledger.

What these dates mean
Report date
The date printed on the office file, or the end of its reporting period. It is not necessarily the date an individual decision was made.
Official data through
The newest decision date inside the latest official file. The decision count belongs to this file only.
Tracker observation
A decision row seen by the tracker outside the latest official file. It is shown separately and is not part of the official count.
Last successful check
The most recent check that successfully read the office file. A later failed attempt does not replace this timestamp.
Last attempt
The most recent scheduled run for the office, whether it succeeded or failed.
Expected next file
Calculated from the latest report date and the office's usual publication rhythm. It is an expectation, not a guarantee.
